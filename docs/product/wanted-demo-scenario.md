# 원티드 3분 데모 시나리오

## 보여줄 한 가지 이야기

Cowork 2.2의 Spring Boot 4 전환을 준비하는 개발자가 수백 개의 새 소식 중 관련 항목을 발견하고, AI의 설명을 검토한 뒤 자신의 AI가 사용할 지식으로 승인한다.

## 장면 구성

### 0:00–0:25 — 정보 과부하

Today 화면에 `15 sources → 247 new → 7 worth your attention`을 보여준다. 실제 샘플 데이터는 6개지만, 숫자는 데모 내러티브용 집계임을 표시한다.

메시지: “더 많은 뉴스를 모으는 것이 아니라 오늘 판단할 양을 줄입니다.”

### 0:25–1:05 — 프로젝트 맥락

`Spring Boot 4.1 migration guide` 항목을 연다.

- 연결 후보: Cowork 2.2
- 관련도: 92% (mock)
- 이유: Spring Boot 4 전환, Elasticsearch client 호환성, Java 21 기준
- 제안: 호환성 검토, 프로젝트 연결, AI 지식 후보 생성

메시지: “일반 요약이 아니라 내 프로젝트에 왜 중요한지 설명합니다.”

### 1:05–1:35 — 사람의 판단

원문을 열어 출처를 확인하고 `프로젝트 연결`을 선택한다. 이어 AI가 구조화한 지식 후보를 보여준다.

사용자는 `수락`을 누른다. 지식 카드에는 source URL, project, confidence, 승인자가 남는다.

메시지: “AI가 제안하지만 학습 여부는 사람이 결정합니다.”

### 1:35–2:15 — 상태 분리

다른 항목에서 사람은 `unread`, agent는 `reviewed`인 상태를 보여준다. 사용자가 `숨김`을 누르면 사람의 Today에서만 제외되고 agent 기록은 유지된다.

메시지: “AI가 읽었다고 내가 읽은 것은 아닙니다.”

### 2:15–2:50 — 활용

Ask 화면 또는 고정 응답으로 “최근 Cowork에 영향을 줄 변화가 있어?”를 묻는다. 방금 승인한 지식과 원문 근거를 포함한 답을 보여준다.

메시지: “읽은 정보가 다음 업무 질문에서 다시 쓰입니다.”

### 2:50–3:00 — 결론

> Don't just read the feed. Teach your AI what matters.

## 데모 안전장치

- 네트워크와 LLM 실패를 피하기 위해 기본 경로는 deterministic mock을 사용한다.
- 관련도 수치는 모델 정확도의 증거가 아니라 UI와 판단 흐름을 위한 샘플이라고 표시한다.
- 원문 열기는 공개 URL을 새 탭으로 여는 수준이며 콘텐츠를 복제하지 않는다.
- 수락과 거절 경로를 둘 다 준비하되 발표에서는 수락 경로 하나만 수행한다.
- 영상 또는 스크린샷 fallback을 준비한다.
