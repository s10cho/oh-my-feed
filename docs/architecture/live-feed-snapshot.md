# 실제 피드 스냅샷

## 목적

제품 방향을 가짜 제목과 숫자로 결정하지 않기 위해 `둘러보기`는 공식 RSS/Atom의 실제 최신 글을 사용한다. 외부 서비스 장애와 브라우저 CORS가 데모를 흔들지 않도록 서버를 상시 운영하는 대신 갱신 가능한 로컬 스냅샷을 사용한다.

## 현재 소스

- OpenAI News — `https://openai.com/news/rss.xml`
- GitHub Changelog — `https://github.blog/changelog/feed/`
- Cloudflare Blog — `https://blog.cloudflare.com/rss/`
- Hugging Face Blog — `https://huggingface.co/blog/feed.xml`

각 소스에서 최신 4개를 가져와 게시 시각으로 정렬한다. 화면은 수집 시각, 실제 제목, 실제 게시일, 원문 URL을 표시한다.

## 갱신

```bash
npm run refresh:feeds
```

결과는 `data/live-feed.json`에 저장된다. 일부 소스가 실패하면 성공한 소스로 스냅샷을 만들고 실패 목록을 함께 기록한다. 모든 소스가 실패하면 기존 파일을 덮어쓰지 않고 명령이 실패한다.

## 현재 한계

- 카테고리는 글 본문 분석이 아니라 소스별 기본값이다.
- 중복 기사 판별은 아직 없다.
- `내 피드`의 관련도와 AI 제안은 실제 글에 연결되지 않은 샘플이다.
- HTML을 제거한 RSS 설명은 내용 파악용이며 정식 요약이 아니다.

## 다음 관찰 항목

실제 스냅샷을 3~5회 갱신하면서 다음을 기록한다.

1. 한 소스가 피드를 과도하게 점유하는가?
2. 소스 기반 카테고리가 실제 글 성격과 어긋나는가?
3. 같은 발표를 여러 소스가 반복하는가?
4. 제목과 RSS 설명만으로 개인화 판단이 가능한가?
5. 프로젝트 입력보다 관심 주제 선택이 초기 개인화에 더 적합한가?
