분석 시점의 원격 저장소는 커밋이 없는 빈 저장소였다.

- README: 없음
- 소스 코드: 없음
- 패키지/빌드 설정: 없음
- 테스트/CI: 없음
- 기존 설계 문서: 없음
- 확정 기술 스택: 없음
- 보호해야 할 기존 애플리케이션 동작: 없음

따라서 이번 브랜치는 기존 구현을 수정하는 작업이 아니라 최초 제품 가설과 경계를 기록하는 작업이다. 이후 기술 선택을 현재 사실처럼 표현하지 않도록, 제안과 확정 결정을 구분한다.

## 이번 브랜치의 기술 원칙

- 프레임워크를 먼저 고르지 않는다. 데모 흐름과 API 경계를 먼저 고정한다.
- 실제 외부 소스와 LLM 호출은 mock으로 대체할 수 있어야 한다.
- 사람의 상태와 에이전트의 상태는 저장 단계부터 합치지 않는다.
- AI가 만든 설명과 지식 후보에는 근거 항목과 승인 상태를 남긴다.
- 원티드 데모 이후 폐기 가능한 코드는 제품 핵심 모델과 분리한다.

## 구현 단계의 후보 스택(미확정)

| 영역 | 작은 MVP 후보 | 선택 시점 |
|---|---|---|
| Web/BFF | Next.js + TypeScript | 첫 UI vertical slice |
| 저장소 | PostgreSQL | 실제 영속화 시작 시 |
| 벡터 검색 | pgvector | 검색 품질 가설이 생길 때 |
| 수집기 | 같은 코드베이스의 scheduled worker | 실제 RSS 연결 시 |
| AI | provider adapter 뒤의 단일 LLM | relevance 평가 구현 시 |
| Agent 연동 | REST 우선, MCP 후속 | 데모에서 외부 agent 호출이 필요할 때 |

별도 backend, 메시지 브로커, 전용 vector DB는 샘플 단계에 필요하지 않다.
